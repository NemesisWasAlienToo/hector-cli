# Torizon OS login test (Hector)

A self-contained [Hector](https://github.com/NemesisWasAlienToo/hector-cli)
project (hector 0.11 or later). It boots the official, unmodified Torizon OS 7.8.0+build.60 image on an emulated Toradex
Verdin iMX8M Plus (Quad, 2 GB, no Wi-Fi/BT) and checks that the boot reaches the login prompt.

```bash
hector test
```

## What `hector test` does

Two `prepare:` steps run on the host before the test. Both need Docker, and both do nothing when
their output is already up to date.

1. **Build the patched Renode image**, `renode-verdin:1.17.0-torizon`, from `renode/`.
   - Upstream Renode at the pinned commit is cloned, `renode/patches/` is applied, and a portable
     build is made.
   - The build is layered onto `antmicro/renode:1.16.1`.
   - The first build needs network access and takes about 15 minutes. After that, Docker's cache
     makes this step take seconds.
2. **Build the boot images** into `images/` with `torizon/prepare-images.sh`.
   - The Tezi tarball is downloaded into `downloads/` (215 MB).
   - From it, the script rebuilds what Toradex Easy Installer writes to the module.
   - It extracts U-Boot and BL31.
   - It writes a Toradex config block (product 0061).

The test then boots the board and waits for `verdin-imx8mp-12345678 login:`. The boot takes about
4 minutes and needs about 3 GB of RAM: the container is capped at 3 GB and 4 CPUs.

## Output

`results/` holds:

- the test reports;
- `console.log`, the board console on UART3 (TF-A, U-Boot, Linux).

## Contents

| Path | Content |
|---|---|
| `.hector.yaml` | Prepare steps, machine, test, and container caps |
| `platforms/toradex-verdin-imx8mp.repl` | Board description. It builds on the i.MX8M Plus SoC description in the patched Renode. |
| `FIXES.md` | What each patch fixes and how the problem was found |
| `renode/Dockerfile` | Builds Renode from source with the patches, then layers it onto the stock image |
| `renode/patches/` | Changes to renode (`8056b03`), renode-infrastructure (`f730546`) and tlib (`5bb3e20`) |
| `renode/renode.config` | Renode config: 64 MiB translation cache per core, so 4 cores fit in 3 GB. Must not contain comments: Renode hangs at startup on them. |
| `torizon/` | Tezi → images: `prepare-images.sh`, which runs `build-image.sh` in a container built from `Dockerfile`, plus helpers `fit_extract.py` (FIT image extractor) and `tdx_cfgblock.py` (Toradex config block writer) |
| `images/`, `downloads/` | Generated by the prepare steps (gitignored) |

## The patches

The patches add:

- new models for the GPC, the system counter and the DDR controller;
- the GIC wake request and the SRC core release;
- tlib fixes for SCR_EL3 interrupt routing and AdvSIMD `st4`;
- a faster generic timer counter and uSDHC DMA;
- PLL, OCRAM_S and DDRC setup in the SoC description.

Each one fixes something that stopped this image from booting or made the boot too slow.
[`FIXES.md`](FIXES.md) explains them and how each problem was found.
